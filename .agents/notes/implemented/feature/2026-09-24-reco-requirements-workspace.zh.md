# Agent Note: RECO 需求工作区呈现

Status: implemented

[English](2026-09-24-reco-requirements-workspace.md) | 中文

## Problem

需求 Notebook、对话导航和右侧栏共同组成桌面工作区，但分离的操作行和不一致的单元格比例弱化了它们的关系。直接用截图替换界面，还可能改变执行行为，或用示例内容覆盖当前 Session 的事实。界面需要在两种语言中建立统一的视觉层级，同时保留已记录的需求工作流。

## Decision

[Figma 桌面端画框](https://www.figma.com/design/JastOBEf9QnfNAqGqyaSIR/Untitled?node-id=67-96)为 RECO 工作区呈现提供参照。对话外壳把已注册的“对话”“轨迹”“需求”标签及切换回调传给需求视图。需求视图把这些标签与“+ 代码”“+ 文本”“全部运行”放在同一导航行。32 px 高的 Session 日志按钮决定标题栏最少为 33 px；40 px 导航行的上下分隔线与右侧栏按 `border-box` 计高的标签行对齐。侧边栏的两个布局按钮位于视口右上角，不占用标签行宽度。当前标签、禁用操作和命令菜单继续反映现有视图与 Task 状态。

Notebook 的文档和 Task 单元格在设计稿的桌面尺寸下按其卡片宽高、内边距、文字层级、选中边框及悬浮操作位置呈现。每个轮次先以本组最大字号显示只读标题，再显示默认折叠的“需求澄清”和需求文档卡。文档卡默认显示紧凑的 Markdown 预览；右上角操作可展开全文，由 Notebook 外层滚动承载，也可恢复预览。单元格仍渲染当前 Session 投影，包括文档修订、Task 状态、执行结果和澄清状态。视口与侧栏调整时保留原有滚动和响应式行为，不把参考图当成固定大小的位图。

Notebook 阅读文字使用与会话共用的持久字号设置：默认 14 px，可在“设置”中调至 12–17 px。轮次、需求澄清、文档和 Task 标题随设置增加 1–3 px；紧凑标签与图谱节点保留各自大小。共用设置避免另建一套仅供 Notebook 使用的字号偏好。

RECO 是可见的产品名称。语言入口保留在左下角“设置”中，需求视图从共享语言设置读取控件文案。界面文字随语言选择变化；用户输入、Agent 输出、路径和代码保留记录的原文。右侧图谱保留四层数据、节点与连线行为、搜索、展开、缩放和详情区；底部输入框仍由对话外壳提供。呈现改动不增加 Session 事件、Remote 或 Agent 步骤。

## Alternatives considered

**另建一套标签栏或需求视图语言入口。** 拒绝，因为重复的视图和语言状态可能与对话外壳及“设置”不一致。传递已注册标签并订阅共享语言设置，可让每项选择保持单一归属。

**用固定的示例文档和 Task 重建截图。** 拒绝，因为示例文字会遮蔽当前 Session 状态，使执行控件产生误导。实时投影提供每个单元格及随状态变化的操作。

**在视觉调整中替换图谱或底部输入框。** 拒绝，因为两者各自拥有独立行为和归属。限定范围的对齐与 Notebook 样式已能组成所需布局，无须改变图谱探索或输入路由。

## Consequences

桌面画框为单元格比例与导航行对齐提供可测量的参照；窄布局仍随可用空间调整。展开长文档会延长 Notebook 的滚动内容，但不改变默认卡片的紧凑状态或底部输入框。视觉和语言检查需要覆盖带真实 Session 数据的场景，因为空白占位无法验证选中、完成、编辑和澄清单元格。需求执行、图谱交互和底部输入保持现有归属及测试。
