# Agent Note: 将计划输出引导为分层任务清单

Status: implemented

[English](2026-09-03-plan-checklist-output.md) | 中文

## 问题

计划模式从 `exit_plan_mode` 接受一个不透明的 Markdown 字符串，因此模型可以生成可读的计划，却不一定使用一致的任务拆解格式。扁平或只有 prose 的计划会增加评审实现顺序、完成状态，以及阶段、任务与具体操作之间关系的难度。

## 决策

仓库的 base、standard、ptc 与 cordis 计划模式 preset 会引导模型在一次 `exit_plan_mode` 调用中，以分层 Markdown 任务清单提交完整计划。中文请求使用 `# 任务列表`；其他请求使用请求语言中的等价标题。该引导要求使用编号阶段标题、稳定的层级任务编号（如 `1.1`）、checkbox 状态，以及列出具体操作的缩进项目。`[x]` 表示在检查期间已完成并验证的工作；`[ ]` 表示拟执行的工作。

需求 Notebook 轮次还会提供一条审批后指令：`todo_write` 按原顺序为每个顶层编号 `## N.` 阶段创建一个 Todo，而不是为每个子勾选项创建 Todo。每个 Todo 先用人话说明整个阶段完成后会得到什么，再从阶段标题开始，完整保留直到下一个 `##` 标题之前的所有 `N.x` checkbox、缩进细节、文件、命令、配置、依赖、实现步骤和验证条件。宿主把第一行作为 Task 标题、其余各行作为技术说明；旧式单行 Todo 继续使用通用 `Task N` 标题。

`dsh-plan-mode` 包继续只校验提交值是非空 Markdown 且以标题开头。部署方仍可控制 `section` 文本，并选择其他输出约定。

## 考虑过的替代方案

**在 `exit_plan_mode` 中解析并强制任务清单。**未采用，因为该工具存储并评审不透明的 Markdown 计划，解析器会在没有提供任务调度或执行语义的情况下，把一种展示约定变成整个包的 wire 要求。

**只向 Web preset 添加格式引导。**未采用，因为 headless 与基于 Cordis 的组合也会挂载计划模式；同一功能在不同 preset 中会产生不同的评审格式。

**自动加载单独的模板文件。**未采用，因为这会给提示词组装增加文件加载依赖，并隐藏部署方拥有的引导。preset 的 `section` 仍是模型指令的显式来源。

## 后果

仓库 preset 产生的计划评审会采用可预期的一次性清单布局，显式呈现阶段顺序、任务状态与实现细节。需求 Notebook 的每个 Task 单元格代表一个完整顶层阶段，先展示人能看懂的阶段结果，再展示该阶段的所有子任务和细节。该格式仍是引导而非校验：模型或自定义部署仍可提交满足现有标题检查的其他 Markdown。仓库修改该引导时必须保持四份 preset 文本一致；自定义部署则可以通过 `section` 覆盖它。

验证覆盖四个 preset 的提示词段、需求 Notebook 双语指令、Todo 到 Task 的投影、配对的包 README、翻译配对一致性，以及现有 plan-mode 行为测试套件。
