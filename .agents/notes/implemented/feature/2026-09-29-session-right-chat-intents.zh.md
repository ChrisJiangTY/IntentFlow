# Agent Note: Session 右侧 Chat 与显式输入意图

Status: implemented

[English](2026-09-29-session-right-chat-intents.md) | 中文

## Problem

需求 Notebook 和图谱占据主工作区，而唯一的完整输入框位于左侧底部。用户阅读 Notebook 和图谱时，必须返回左侧边缘才能提交内容。Chat 记录还占用独立的主标签页，因此无法同时查看 Notebook 与对话。单一且未区分的提示词提交无法可靠地区分普通对话、需求修订和独立任务。

## Decision

右上角第一个面板按钮在现有右侧栏之上打开 Chat。它沿用侧栏可拖动的宽度，关闭后恢复侧栏此前的内容。右侧 Chat 读取当前 Session 的 Conversation binding，显示与左侧 Chat 标签页相同的记录；它不创建第二个 Session 或 Agent。新建的空白 Session 保留居中的 Hero 输入框，用于提交首条提示词。打开右侧 Chat 时，该输入框移到右侧；首轮开始后，左侧 Chat 只显示记录，完整的 Session 输入框位于右侧 Chat。切换 Session 时，两处记录和输入框同步切换；独立的子代理对话留在 Chat 覆盖层下方的侧栏中。

用户从右侧输入框提交普通提示词时，先选择普通对话、需求或独立任务。取消会保留草稿。普通对话沿用现有 Session 发送路径。提交需求会给该 Session 最近的需求轮次追加一份新修订，并保留较早修订和 Task 结果。提交独立任务会创建一个仅含待执行 Task、没有需求文档的任务轮次；用户通过现有 Task 控件显式运行它。系统按用户选择路由输入，不根据提示词文字或当前主标签页猜测意图。

右侧 Chat 复用 Conversation 的记录和输入行为，包括附件、引用、命令、权限与模型控件、排队、转向和停止。该面板按钮不再打开底部终端，而是控制右侧 Chat 覆盖层。意图只影响普通提示词提交，原有命令与交互处理仍由既有模块负责。

Web minimal 预设明确只允许自身的 bash 和编辑器工具。工具策略应用在选中的 Agent 作用域，子代理会继承；空白 Session 切换预设时，先检查配置的工具名称，再替换策略。Web 测试脚手架叠加测试配置时保留产品自带的预设策略。

预览打包器从 Loader 条目收集裸包名，仅对 group 条目递归读取嵌套配置，从声明依赖的工作区解析包，并将显式列出的外部 Loader 入口保留为可达根节点。打包后的 Web 镜像检查覆盖实际的 Better Sidebar 模块入口。Better Sidebar 的 API 和上传请求在存在现有 worker 通道时经该通道发送；普通 Web 页面仍使用浏览器 fetch。预览上传传递该通道支持的原始 `ArrayBuffer` 字节。

## Alternatives considered

**把 Chat 加成侧栏标签页。** 用户要求在侧栏既有尺寸中完整覆盖，并在关闭后恢复原来的文件、图谱或子代理内容。标签页会改变侧栏选中状态，使恢复行为取决于标签历史。

**打开独立的 Chat Session。** 第二个 Session 会拆分日志、Agent 状态和上下文，导致右侧记录与左侧 Chat 可能不一致。因此两处视图使用同一个 Session binding。

**根据文字或当前主视图推断意图。** 无论选中哪个标签页，提示词都可能是问题、修改需求或直接任务。在单独设计模型路由前，显式选择使输入路径清楚可见。

**把独立任务写进需求文档。** 这会为用户明确指定的直接任务虚构文档和需求节点。任务轮次直接记录 Task，不伪造需求修订。

## Consequences

两处 Chat 显示共用一个 Session 日志和一份输入状态。右侧面板宽度限制了记录与输入框的空间，但用户可以通过现有拖动控件调整。追加需求必须保留历史执行证据，同时把当前文档和 Task 列表推进到新修订。任务轮次没有文档，因此需要明确的投影和图谱处理。意图弹窗为普通提示词提交增加一次选择，取消时草稿保持原样。
