# Agent Note: Notebook 交付结果

Status: implemented

English | [中文](2026-09-15-notebook-delivery-results.md)

## 问题

进度消息和验证报告掩盖了任务实际交付的内容。人需要看到产品结果及其限制，而不必阅读执行记录。

## 决策

任务执行要求最终回复恰好包含两个部分：交付结果和说明。宿主保存最后一条非空助手回复，不拼接进度消息。原始消息和工具证据保留在 Session 日志中。

Notebook 解析 Markdown，仅展示可识别的交付章节，包括历史的交付文件标题。它保留链接，在交付章节缺失时显示明确占位提示。说明、审核摘要和额外提示不属于结果展示；Task 状态标记仍区分失败与完成。独立审核仍读取完整执行证据。

本决策收窄[Notebook 流水线](2026-09-02-requirement-notebook-pipeline.zh.md)中的结果展示；其身份、审核和持久化决策继续有效。

## 考虑过的替代方案

**只修改提示词。** 历史报告仍然冗长，模型追加说明时也无法约束实际显示的章节数。

**让另一个模型重写每份已保存结果。** 这会增加延迟，并可能改变交付声明。确定性的章节选择保留原始结果，不增加模型请求。

**删除详细证据。** 这会妨碍独立审核和问题调查。展示层隐藏无关章节，但不删除原始事件。

## 影响

非结构化历史报告显示占位提示，仍可在详情和轨迹中查看；浏览器不从任意文字推断交付物。章节选择无法证明声明真实，也不能阻止可识别章节内部出现无关文字。执行状态和独立审核仍是权威依据。

## 测试

组件与解析器测试覆盖历史标题、链接、代码围栏中的伪标题、缺失章节，以及隐藏进度和验证文字。宿主测试区分进度与最终回复。录制的 Web 任务结果场景在录制时使用真实模型执行最终报告提示词和独立审核，并在之后进行无密钥回放。
