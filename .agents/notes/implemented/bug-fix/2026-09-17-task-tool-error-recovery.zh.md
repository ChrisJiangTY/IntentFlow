# Agent Note: Task 工具错误恢复与长时间运行诊断

Status: implemented

[English](2026-09-17-task-tool-error-recovery.md) | 中文

## Problem

任何工具失败都取消 Task，会阻止实现 Agent 自行恢复。文件版本过期的编辑需要重新读取；失败的命令可能需要修正后重试。这些情况都不能证明 Task 或 Agent Turn 已失败。但无界的问题执行仍需要独立诊断。

## Decision

需求控制器不会因原生或嵌套工具错误、Bash 失败、信号或命令超时取消 Task。普通实现 Turn 正常结束即完成 Task。非正常 Turn 结束和用户明确停止仍会停止按序执行。检查点与本轮最终审核使用同一独立审核者。

每次执行达到可配置的一小时运行时长后，启动一次只读子 Agent。子 Agent 检查有长度上限的 Task 与当前 Turn 证据时，主任务继续运行。只有正常完成且包含原因和具体证据的 `stop` 判定，才能停止同一次活动执行。工具失败、运行时长和未完成工作本身都不足以停掉任务。健康、无法确定、不可用、格式错误或超时的诊断均让 Task 继续运行。子 Agent 有单独可配置的五分钟超时，不能继续派生后代。Task 结算、Session 销毁和插件销毁都会中止诊断；过期结果不能停止后续工作。

本文部分替代[集中需求审核](../feature/2026-09-16-batched-requirement-review.zh.md)中工具失败立即取消的决定。该文仍负责审核频率、按序执行与最终图谱验证。本实现使用需求插件的生命周期钩子，不修改核心 Agent Loop。

## Alternatives considered

**每次工具错误都停止。** 予以放弃，因为预期的可恢复错误会阻止 Agent 收到反馈并修正做法。

**一小时后自动停止。** 予以放弃，因为运行时长无法区分有效工作与循环。诊断先提供证据，再决定是否取消。

**每个 Task 后运行验收审核者。** 予以放弃，因为运行健康与需求验证服务于不同目的；重复验收审核会拖慢整个运行。

## Consequences

可恢复的工具错误保留在正常的模型可见记录中。长任务增加一次诊断调用，而非周期审核调用。诊断证据有长度上限，可能漏掉问题；插件重新加载后不恢复运行时计时器。取消不会回滚已有文件修改。无需修改 Session 事件格式。

## Testing

定向测试覆盖原生与嵌套工具错误恢复、真实 Agent Loop 在 Bash 非零退出后继续执行、正常完成、一小时调度、有证据的停止与继续判定、无效判定、诊断超时、迟到结果和销毁。检查点与本轮最终审核测试保留验收审核行为。
