# Agent Note: Notebook 状态独立于聊天历史

Status: implemented

[English](2026-09-15-notebook-history-retention.md) | 中文

## 问题

聊天历史窗口被最近一页替换时，Notebook 可能丢失可见单元格。任务更新仍在这一页中，但来源文档已在窗口外，浏览器因此隐藏整个任务列表。已保存内容必须在刷新和重连后保持可用，重新运行任务也必须保留此前的交付结果。

## 决策

宿主把完整 Session 日志折叠为 `requirementNotebook`。它保留文档修订、每个文档修订的最新任务列表、单元格最新值，以及每次任务执行。浏览器独立于聊天事件窗口订阅这一投影。标准投影序列规则会在较新更新到达后拒绝旧基线。已有 Session 会从持久日志重建投影。

Notebook 保持旧文档任务可见且只读，按产品轮次编号排列轮次，并渲染每次执行的交付结果。编辑人类说明或开始另一次执行不会抹去此前交付。[Notebook 流水线](../feature/2026-09-02-requirement-notebook-pipeline.zh.md)继续负责编辑和编排；本决策只取代其中基于历史窗口的重建机制。[交付展示](../feature/2026-09-15-notebook-delivery-results.zh.md)继续只提取交付章节。

## 考虑过的替代方案

**增大聊天分页大小。** 予以放弃，因为 Session 增长后，任何有限尾页都可能遗漏更早的文档或单元格。

**只在浏览器内存中保留旧单元格。** 予以放弃，因为新页面或另一浏览器仍缺少被遗漏的历史，而且累积值可能掩盖保存失败。

**为 Notebook 加载全部聊天历史。** 予以放弃，因为重建任务单元格不需要工具输出或模型流式历史。独立投影只携带所需的持久记录。

## 影响

已保存的 Notebook 内容可在聊天分页和传输替换后保留，无需模型调用。投影大小随文档修订、单元格、审核和执行次数增长，但不包含无关工具事件和模型流式事件。未确认的编辑仍是本地草稿；本决策不会把失败的自动保存变成持久内容。

## 测试

录制会话投影测试验证重建和持久化 schema 校验。组件测试验证另一次执行期间保留此前交付，以及旧文档任务保持只读。导航浏览器场景在产生超过一页的后续消息后恢复编辑后的任务、备注和交付结果，刷新浏览器，并强制 WebSocket 重连后接收另一个已保存备注。
